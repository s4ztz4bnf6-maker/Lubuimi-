# JARVIS Algorithmus — architecture and governance
SPDX-License-Identifier: Apache-2.0
Owner project: JARVIS. Trading baseline supplied by Ta-Yoshua Lubuimi; preserve attribution.
Modules: second-good-life, trading, sales, chat, bounty, exchange, finance, cybersecurity.
Each module must expose version, source export, metrics, inputs, evaluation history, rollback and license.
Optimization: maximize verified net contribution after costs and risk; chat and security also require quality and safety constraints.
Learning loop: collect authorized timestamped observations, propose candidate parameters, evaluate on held-out data, compare with incumbent, record results, require approval for production changes affecting risk, permissions or spending.
No autonomous rewriting of guards, credentials, permissions or deployment policies. No paid data or trades without owner approval.
Trading: backtest and paper only; no live orders. Preserve user baseline separately. Validate positive prices, complete region map, probabilities, time ordering, transaction costs, single-asset correlation, no lookahead, next-session execution, out-of-sample walk-forward, stress tests and drawdown limits. Scenario inputs must be timestamped and sourced.
SGL: verified offers and wanted listings only for confirmed matches; discovery leads are not customers. Net margin after actual logistics costs; no booking without approval and funds.
Status: architecture specification, not runtime implementation.
